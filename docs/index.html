Introducing Weight Space Modifiers

Can a teacher improve a neural network by changing its weights directly?

WSM gives you a way to test that idea. A teacher suggests new numbers. WSM tests them and keeps the change only if it improves the result. The network's structure stays the same.

The core loop

Show the teacher the current network and its results. Ask for a change. Test the change against the best version so far.

  1. inspect returns a copy of the current weights and feedback.
  2. submit tests a proposed change. Better results replace the current best version. Other changes are rejected.
  3. finish ends the experiment and returns its saved record.

You can also run the steps separately with propose, evaluate, and select.

Roles in one run

Teacher
Suggests which weights to change and what values to use. In this example, a file supplies the suggestions. No AI model is called.
wsm.binary64
Runs the small network used in this example.
SearchRun
Tracks the experiment, limits the number of attempts, and keeps the best weights under your chosen scoring rule.
Evaluator
Tests the changed network and returns scores. This example uses NumericalEvaluation on your machine.
Trusted task code
Chooses the examples used for feedback and keeps separate examples for the final test.

One accepted proposal

A proposal says which version to change and which numbers to replace. Here, it sets the two output weights to 1 and -1.

base identifies the current saved network, called a checkpoint. The demo gets this ID from inspect. Each edit names an array of weights in tensor, a position in index, and a new value.

{
  "base": "sha256:1554696f55aac47c67222c16d87bd6fc22512428409cac4f4a17a5ab0246e271",
  "author": "scripted-teacher",
  "edits": [
    {"tensor": "output.weight", "index": 0, "value": 1},
    {"tensor": "output.weight", "index": 1, "value": -1}
  ]
}

Positive and negative branches

The example starts with useful wiring already in place. One branch carries a positive sum. The other carries the size of a negative sum. ReLU keeps positive values and turns negative values into zero.

The output weights start at zero, so the network always answers zero. Setting them to 1 and -1 combines the two branches into signed addition.

For 3 + (-1), the branches hold 2 and 0. The output is 2. For -3 + 1, they hold 0 and 2. The output is -2.

The offline tutorial lets you change those output numbers in the browser. That calculation does not submit a proposal to the Python run.

Three scripted decisions

The demo tries three changes in order. Each starts from the best version kept so far.

  1. Change the first output weight to -1. Positive sums get the wrong sign. Reject.
  2. Change both output weights to [1, -1]. All training and development examples get the right answer. Keep.
  3. Add a bias of 1 to the accepted version. Every answer is now too large by 1. Reject.

Strict selection

The example compares error on the development examples first. Lower error wins. If that score ties, it compares training error. If both tie, it keeps the current version.

Before testing the first change, WSM scores the starting network. If that test fails, it cannot accept a change. A failed test of a proposed change cannot win either.

The experiment contract gives the exact scoring and decision rules.

Finish and replay

finish closes the experiment and saves its best weights and recorded results. It does not run more tests.

replay rebuilds those weights from the record and checks that the recorded decisions agree with the scores. It does not rerun the tests or prove who produced the scores. Someone could rewrite a whole unsigned record.

To check the final network, test it separately on heldout examples, meaning examples kept out of the feedback loop. Keep those final scores out of later edit decisions.

What the demo shows

The addition demo checks that proposing, testing, and keeping weight changes works. Its proposals are written in advance. It does not show an AI discovering the solution.

For tests in Docker, use the optional Harbor integration. The architecture guide explains how it works. The verification guide records the checks.

The durable local client adds experiments you can resume, a live teacher connection, and Docker workers for the small network and a fixed version of SmolLM2. These are separate from the offline demo.

WSM is inspired by a research preprint. This small, synthetic example does not reproduce the paper's results or show that direct weight edits outperform other methods. Read the research scope for those limits.

Run the example

From the repository root, use Python 3.12 or later with venv and pip available. The core package has no runtime dependencies. On Debian or Ubuntu, install the matching python3-venv package if creating the environment reports that ensurepip is missing.

python3 -m venv .venv
.venv/bin/python -m pip install -e packages/python
.venv/bin/python examples/demo.py --output /tmp/wsm-run.json

For the proposals in the repository, the demo prints these three lines.

{"accepted": false, "reason": "not_improved"}
{"accepted": true, "reason": "improved"}
{"accepted": false, "reason": "not_improved"}

The frozen run is written to /tmp/wsm-run.json.
